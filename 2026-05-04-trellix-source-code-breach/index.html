セキュリティ企業が破られるとき——Trellixのソースコード流出が意味すること

皮肉な被害者

Trellixはセキュリティ企業だ。

2022年にMcAfee EnterpriseとFireEyeが合併して設立された。両社ともサイバーセキュリティの老舗で、企業や政府機関のセキュリティ製品・サービスを提供してきた。脅威インテリジェンス、エンドポイント保護、ネットワーク監視——攻撃者の手口を調査し、防御策を売ることが業務だ。

そのTrellixが、自社のソースコードリポジトリへの不正アクセスを認めた。

ソースコードが流出するとはどういうことか

データ流出の種類は様々だが、ソースコードは特殊なカテゴリに属する。

顧客データや認証情報が流出した場合、影響はその情報の直接的な悪用に限られることが多い。しかしソースコードが流出すると、攻撃者は製品の「中身」を見ることができる。

セキュリティ製品の場合、これは特に危険な意味を持つ。

  • どのパターンを検知しているか（逆算して回避できる）
  • どこに脆弱性があるか（製品自体を攻撃できる）
  • どのように動作するか（模倣やトロイの木馬化に利用できる）

Trellix自身は「ソースコードのリリースや配布プロセスへの影響、またはソースコードが悪用されたという証拠は見つかっていない」と述べている。しかしソースコードを持った攻撃者が長期的に何をするかは、今後の問題だ。

「攻撃者を最もよく知る」企業が狙われる理由

セキュリティ企業は、攻撃者にとって魅力的な標的だ。

理由の一つは、上で述べたソースコードの価値だ。もう一つは、セキュリティ企業が扱うインテリジェンス情報の価値だ。FireEyeは2020年にも侵害を受けており、そのとき盗まれたのはレッドチームツール（攻撃者の手口を模倣したテストツール）だった。

そして三つ目の理由がある——セキュリティ企業は、多くの企業の防御インフラに深く埋め込まれている。エンドポイント製品、SIEMとの統合、脅威フィード——ここを取ることは、その下流にいる多数の企業への足がかりになる可能性がある。

これはサプライチェーン攻撃の観点だ。SolarWindsが狙われたのも同じ理由だった。

「専門家だから安全」は成立しない

セキュリティ企業が侵害されるたびに、ある種の不快感が漂う。

彼らは攻撃者の手口を誰より知っている。製品として防御ソリューションを売っている。にもかかわらず、自分たちが標的になる。

これは「セキュリティ企業が無能だ」という話ではないと思う。むしろ逆で、知識と能力がある組織でさえ100%の防御は成立しない、という現実の表れだ。

攻撃者には時間がある。特定の標的に対して、長期間かけてアプローチを試み続けられる。どこかに必ず侵入できるまで続ける。「ゼロデイ」と呼ばれる未知の脆弱性も、潤沢に手に入れることができる組織が存在する。

Trellixの事案が示すのは、守る側であることが免罪符にはならないということだ。

自分が使っているセキュリティ製品について

今回の件で、Trellixの製品を使っているユーザーは何をすべきか。

Trellix自身が「製品への影響の証拠はない」と述べており、現時点でパニックになる根拠はない。しかし、セキュリティベンダーが侵害されたとき、ユーザーにできることは限られる——情報を注視し、ベンダーからの続報を待ち、異常な動作があれば報告する、程度だ。

それ自体が、セキュリティというものの性格を示している。完全なコントロールはどこにもない。
