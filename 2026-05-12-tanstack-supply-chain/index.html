「有名で実績のあるライブラリ」でも安全ではない

TanStack（タンスタック）はReact開発者の間で広く使われているライブラリ群だ。週数百万件ダウンロードされる @tanstack/router をはじめ、84のパッケージが5月11日に一斉に侵害された。

攻撃者がOIDCトークン（GitHub ActionsのCI/CDパイプラインで使う認証トークン）を窃取し、プロジェクト自身のリリースパイプラインを経由して難読化された悪意あるペイロードを注入した。Socket Securityは公開から6分以内に全悪性バージョンを検出した。

自己増殖ワームとはどういうことか

通常のサプライチェーン攻撃は「悪意あるパッケージを公開し、誰かがインストールするのを待つ」型だ。

今回の攻撃は違う。「Mini Shai-Hulud」と呼ばれるこのワームは、感染したリポジトリのパイプラインを踏み台にして次のリポジトリへと拡散する。TanStack→Mistral AI→UiPath→OpenSearch→Guardrails AIと連鎖した。

ワームが「公式リリースの姿をとって」拡散するため、外形上は正規パッケージと区別がつかない。バージョン番号があり、npmレジストリに載り、メンテナーの認証情報で署名されている。

なぜOIDCトークンが狙われるか

GitHub ActionsのOIDCトークンは、CI/CDパイプラインの各ステップで一時的に発行される短命のトークンだ。このトークンが「パッケージのリリースに必要な権限」を持っていた場合、窃取されれば攻撃者はそのプロジェクトの公式リリースを乗っ取れる。

Aikido Securityが公開したGitHub Actionsセキュリティチェックリストでは、多くの大規模サプライチェーン攻撃の起点がGitHub Actionsの設定ミスだと指摘している。「defaultのpermissionsを使っている」「secrets.GITHUB_TOKENに必要以上の権限を与えている」ケースが多い。

開発者が今週できること

  • package-lock.json をコミットし、予期しないバージョンアップを防ぐ
  • GitHub Actionsのpermissionsをjobレベルで contents: read など最小限にする
  • CI/CDのリリースstepにのみ必要な権限を絞って渡す
  • Socketのようなサプライチェーン監視ツールの導入を検討する

「有名なライブラリだから安全」という仮定は、サプライチェーン攻撃の存在によって成立しなくなっている。
